# AY Shadow V7.1 Stability Update

**Target**: Realme 7 Pro (RMX2170), Android 14 MelloDerp, Linux 4.14.357 Qualcomm atoll.

This is a stabilization release, not a CPU/GPU overclock, battery drain guarantee, or kernel panic fix.

## Verified source changes

1. **Accurate DeepDoze entry count**. `deep_entries` increments only on the first 0→1 transition after a 600 s BOOTTIME screen-off deadline. Existing PM_POST_SUSPEND notifications after successful or aborted suspend no longer keep queuing another DeepDoze attempt once enabled. `doze_rearm_skips` measures prevented requeues.
2. **Reduced CPU policy refresh work**. Ordinary touch and rapid tap extend 800 ms/450 ms boost windows without requesting another policy update if the floor remains the same. On a new boost level or expiration, the policy worker is queued and refreshes the unique online CPUFreq policies. `touch_refresh_skips` counts avoided touch-triggered refresh requests, not CPU frequency changes; `policy_refreshes` counts worker invocations, not MHz changes.
3. **Thermal samples remain active** on a 5 s period while screen on. A CPU policy refresh is now queued only if the thermal-safe state changes or Turbo is stopped. The 37.5 C Turbo cutoff and 40 C touch/game cutoff are unchanged.
4. **Native services preserved**: DSI physical panel events; original Novatek NT36672C DT2W and IRQ wake; optical fingerprint; KernelSU Next 33355 with SUSFS 2.3.0; Android's `alarmtimer`, wakelock logic and thermal limits unchanged.
5. **Passive suspend audit**: `scripts/v7_1_suspend_audit.sh` captures and compares /sys/power/suspend_stats and /proc/wakeup_sources using boot_id to avoid false deltas after reboot. It does not modify kernel parameters or alarm scheduling.

## Release verification

- Full pinned-source kernel build in .github/workflows/v7_1.yml.
- `CONFIG_LOCALVERSION="-AY-Shadow-V7.1-Stability"` and required KernelSU/Fingerprint/DT2W configuration flags.
- Complete before/after device validation required: boot identity, KernelSU Manager, fingerprint, touchscreen DT2W, root, charging, alarms, calls, 11-minute screen-off and wake, thermal behavior, battery drain, restart. Build success alone is insufficient.

## Device sanity check

```sh
su -c 'cat /proc/version; id; cat /sys/kernel/ay_shadow/telemetry'
```

After one screen-off interval longer than 11 minutes, `deep_entries` should increment **once**, not once for each aborted suspend or PM_POST_SUSPEND notification. `cap_applied` may be zero if the phone stays suspended until screen-on, and this alone is not proof of failure. A `restore_ms` value is CPU policy refresh latency, not physical display wake latency.

To collect same-boot suspend deltas, run `sh scripts/v7_1_suspend_audit.sh before`, turn screen off for ~11 minutes, then `sh scripts/v7_1_suspend_audit.sh after`, from a root shell on the phone.

## Flashing cautions

- Only a **compiled, validated, RMX2170 model-checking OrangeFox AnyKernel3 ZIP** is flashable.
- Raw GitHub `Image.gz-dtb` is **NOT** a ZIP flash installer.
- Keep a pre-flash boot image backup and the proven V7 ZIP.
- AnyKernel packaging preserves V7 field-tested DTBs and leaves system/vendor/DTBO untouched.
- Treat V7.1 as **experimental** until real hardware validation proves stability.
